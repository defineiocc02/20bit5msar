# RA OU + RX N256：ID138 半 LSB 舍入回放

**结论：**实际保存的 MATLAB 仿真在 RX ID138 输出 **91643**。Python 独立重算采用 `np.sum` 时得到 **91642**；采用本机 `np.dot` 时得到 **91643**。差异出现在双精度 D2 位权求和，未舍入码正好落在半整数附近。本次没有修改原始码、原始数据或判断阈值。

## 原始记录及数值

实际接收时间为 `28.138 µs`，公开记录为 `RAW6=[201,2764,108,138,1,1]`；实际 `code_log=91643`。同一实际 RX ready 时刻保存的 FPGA 电压分项为：

| 项 | 实际保存值 |
|---|---:|
| D1 | −3.3840000000000003 V |
| D2 | +0.003953125000000005 V |
| DT | +0.00000390625 V |

以保存的公开参数和 RAW 位重算：`D2_RA = -0.5095 + Σ(weight[k] × bit[k])`，`D2 = D2_RA / 32`；再按 `((D1+D2)+DT)×(2^20/8.192)+2^19` 计算未舍入码。dither 和 AZ 均关闭。

| D2 求和方式 | 位权乘积之和 [RA V] | 折回输入的 D2 [V] | 未舍入码 | 最近值、半数远离零 | 与实际码一致 |
|---|---:|---:|---:|---:|---|
| Python `np.sum(weights * bits)` | 0.636 | 0.003953125000000002 | 91642.49999999994 | 91642 | 否 |
| Python `np.dot(weights, bits)` | 0.6360000000000001 | 0.003953125000000005 | 91642.5 | 91643 | 是 |
| 实际记录的 D1/D2/DT 分项 | — | 0.003953125000000005 | 91642.5 | 91643 | 是 |

`np.sum` 的 D2 为 `0x1.03126e978d500p-8`，实际保存的 D2 和本机 `np.dot` 均为 `0x1.03126e978d504p-8`。MATLAB 的正半整数按远离零舍入，因此 `91642.5 → 91643`。实际 runner 在原生运行时对每条 RX RAW 调用 `behavior_decode` 并检查输出码；其独立函数内部的 D2 中间量**没有单独保存**，不能把 FPGA `d2_log` 冒充该函数内部探针。

## 全部 260 条 RX 记录的口径

- 按实际保存的 D1/D2/DT 分项重组并按同一规则舍入：**260/260 整数码完全一致**。
- 本机 `np.sum` 公开码权重算：**259/260** 与实际整数码一致，唯一差异为 ID138。
- 本机 `np.dot` 公开码权重算：**260/260** 整数码一致；但其 D2 分项只有 **213/260** 与实际日志浮点值完全相等，另有 47 条分项存在微小差异。整数码一致不能证明 D2 内部每一步逐位相同。
- `np.sum` 的 D2 分项有 **166/260** 与实际值完全相等；两种 Python 求和的 D2 最大绝对差均为 `3.469446951953614e−18 V`。这些数值作为观察，不被用作放宽整数码比较的容差。

整数码比较的允许误差始终是 **0 码**。不能把 `np.sum` 的 ID138 差异静默改成通过，也不能据此断言实际 ADC/RTL 错误。当前 `np.dot` 结果只说明本机这一批记录的重算结果与实际整数码一致；BLAS、NumPy 或机器改变可能改变浮点归约顺序，不能据此保证所有平台都复现 MATLAB 内部求和。

本次结果使用 Python 3.12.14、NumPy 2.5.4、macOS arm64。噪声 σVX＝1 mV 是隔离行为模型测试假设，不说明论文 7 dB 或物理噪声性能。候选源码、实际 run 和任何结果门均未因该差异修改。
