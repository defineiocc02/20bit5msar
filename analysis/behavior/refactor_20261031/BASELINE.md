# 整图数值回归基线（内核改动前置条件）

日期：2026-10-31。

## 目的

为剩余内核文件（`behavior_frontend_step` 等）的改动建立可判定的数值门禁。

## 1. 先确认模型是否确定性 —— 这一步最关键

如果同配置两次运行结果不同，任何数值门禁都无意义。所以先做复现性检验。

### 第一次尝试：分组错误，得出错误结论

我按 `(N, f, amplitude, ktc, ra, epoch)` 分组，得到 24 个"同配置"run，
SNDR 跨度 **52.9 dB**，一度以为模型不确定。

**这是错误的。** 逐个字段比对后发现同组内还有 **40+ 个字段不同**：
`front.C_f`、`front.jitter.enabled`、`front.tau_sample_s`、`transport.enabled`、
`bank.enabled`、`frozen.enabled`、`debug.*`、`cal_cfg.*`……

真正的判据是**整份 `parameters.json` 的 SHA-256**，不是我挑的几个顶层字段。

### 正确分组后的结论

| 判据 | 结果 |
|---|---|
| 按整份 params 哈希分组 | **9 组**真正同配置 |
| 覆盖 run 数 | 21 |
| 5 项指标（SNDR/SNR/SFDR/THD/ENOB）最大跨度 | **0.000e+00** |
| 结论 | **模型完全确定性，逐位可复现** |

**数值回归门禁可行。**

## 2. 代价结构（修正一个我此前说错的数）

| 记录长度 N | 每 run 转换数 | 耗时 | 能算 SNDR |
|---|---:|---|---|
| 8 | 8 | 3–14 s | ❌ 只有 INL/DNL（`behavior_spectrum` 返回 `not_run_short_capture`） |
| 256 | 256 | **64.6–140 s**（中位 74.4） | ✅ 完整频谱 |

我之前用 N=8 的 3 秒去否定"75 秒"这个数，**是搞错了对象**。
75 秒就是 N=256 频谱 run 的成本，那个数字是对的。

**内核改动的每次验证成本 = 约 75 秒。**

## 4. 一个必须记下的方法论教训

本轮我连续犯了两次同类错误：

1. 用 **N=8 的 3 秒**否定 **N=256 的 75 秒** —— 对比对象错了
2. 用 **6 个顶层字段**判断"同配置" —— 判据不完整，导致 52.9 dB 的假差异

两次都是**验证口径设计有误**，而不是被测对象有问题。

**教训：比数值之前，先证明"两次比的是同一个东西"。**
